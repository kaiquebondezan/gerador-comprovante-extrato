ColmeIA Bank API

Uma API HTTP simples, sem autenticação, que gera comprovantes fictícios de transferência (Pix) em PDF e/ou PNG. Construída para simular o bot de um banco em ambiente de teste — nunca para representar uma instituição real.

Visão geral

A API expõe um único endpoint de negócio, POST /comprovante, que recebe os dados de uma transferência em JSON e devolve um comprovante pronto — em PDF, em PNG, ou os dois. Não existe login, chave de API ou sessão: qualquer requisição bem formada é atendida.

Por baixo, é um servidor Node.js + Express que renderiza um template HTML/CSS e usa o Playwright para controlar um Chromium headless, que imprime esse HTML como PDF ou tira um screenshot dele como PNG. Não há banco de dados: cada requisição é independente e nada fica salvo.

Como funciona

Do request até o arquivo final, o caminho é sempre o mesmo pipeline:

01

Request chega

JSON com valor, recebedor e pagador em POST /comprovante.

02

Validação

Confere valor, recebedor.nome e pagador.nome. Falta algo → 400.

03

Template preenchido

Dados + data/hora/ID/protocolo automáticos entram no HTML do comprovante.

04

Chromium headless

Playwright abre o HTML numa página invisível e a renderiza.

05

PDF / PNG

page.pdf() ou elemento.screenshot() viram a resposta.

Por que um navegador headless para gerar PDF?

Em vez de desenhar o comprovante programaticamente (linha a linha, como bibliotecas de PDF tradicionais fazem), o projeto escreve o layout uma vez em HTML/CSS — a mesma linguagem usada para qualquer página web — e deixa o motor de renderização do Chromium cuidar de tipografia, espaçamento e alinhamento. Isso torna o design tão fácil de ajustar quanto editar um site, com o mesmo resultado visual em PDF e em PNG.

⬡

O Chromium é iniciado uma vez (na primeira requisição) e reaproveitado nas seguintes — só uma nova aba é aberta por requisição. Isso evita o custo de abrir um navegador inteiro a cada chamada.

Instalação & scripts

Requer apenas Node.js instalado. Na pasta do projeto:

bash
npm install
npm start

npm start confere se o Chromium do Playwright já está instalado e, se não estiver, baixa sozinho antes de subir o servidor — não é preciso rodar nenhum comando de instalação do navegador manualmente.

ScriptO que faz
npm startGarante o Chromium instalado e sobe o servidor uma vez.
npm run devIgual ao start, mas reinicia sozinho a cada arquivo salvo (nodemon).

Query params

ParamValoresDescrição

Exemplo — PDF

bash
curl -X POST "http://localhost:3000/comprovante?format=pdf" \
  -H "Content-Type: application/json" \
  -d @exemplo.json -o comprovante.pdf

Exemplo — os dois formatos

bash
curl -X POST "http://localhost:3000/comprovante?format=both" \
  -H "Content-Type: application/json" \
  -d @exemplo.json
response 200 (format=both)
{
  "pdf_base64": "JVBERi0xLjQK...",
  "png_base64": "iVBORw0KGgo..."
}

Corpo da requisição

Todos os campos abaixo são lidos do JSON enviado no POST /comprovante.

json
{
  "titulo": "Pix enviado",
  "valor": 80.00,
  "protocolo": "202608261234567",
  "logo_base64": null,
  "recebedor": {
    "nome": "Loja Exemplo LTDA",
    "cpf_cnpj": "23010551000131",
    "instituicao": "Banco Exemplo S.A."
  },
  "pagador": {
    "nome": "FULANO DE TAL",
    "cpf_cnpj": "12345678909",
    "instituicao": "ColmeIA Bank"
  }
}
CampoTipoDescrição
valornumber obrigatório Valor da transferência. Formatado automaticamente como R$.
recebedor.nomestring obrigatório Nome de quem recebe.
pagador.nomestring obrigatório Nome de quem paga.
recebedor.cpf_cnpjstring opcional 11 dígitos (CPF) ou 14 (CNPJ). Mascarado automaticamente no comprovante.
pagador.cpf_cnpjstring opcional Mesma regra de máscara do recebedor.
recebedor.instituicaostring opcional Texto livre exibido em "Instituição".
pagador.instituicaostring opcional Texto livre exibido em "Instituição".
titulostring opcional Título acima do valor. Padrão: "Transferência enviada".
protocolostring opcional Se omitido, a API gera um número aleatório de 15 dígitos.
logo_base64string opcional PNG em base64 do símbolo. Se omitido, usa public/default-logo.png.

Sobre a máscara de documento: 11 dígitos viram ***.XXX.XXX-** (CPF); 14 dígitos viram **.XXX.XXX/XXXX-** (CNPJ) — o mesmo padrão usado por bancos reais em comprovantes.

Campos automáticos

Estes campos nunca vêm do corpo da requisição — a API sempre os calcula ou fixa sozinha. Se você enviá-los mesmo assim, são ignorados silenciosamente.

  • banco_nome / brand_colorSempre "ColmeIA Bank" / #4d4d4d — fixos no código, não configuráveis por request.
  • data_pagamento / horarioData e hora do instante em que a requisição chega, sempre no fuso America/Sao_Paulo — independente de onde o servidor estiver rodando.
  • id_transacaoGerado a cada request no mesmo formato de um EndToEndId de Pix ("E" + 8 dígitos + data/hora UTC + 11 caracteres alfanuméricos). Só estética — não corresponde a uma transação real.

Erros de validação

Se valor, recebedor.nome ou pagador.nome estiverem faltando (ou valor não for um número), a API responde 400 em vez de gerar um comprovante com campos em branco:

response 400
{
  "error": "Dados inválidos no body da requisição",
  "details": [
    "'valor' é obrigatório",
    "'recebedor.nome' é obrigatório"
  ]
}

Um format fora de pdf/png/both também retorna 400. Falhas internas ao renderizar (ex.: Chromium indisponível) retornam 500 com error e detail.

Formatos de resposta

formatContent-TypeCorpo
pdfapplication/pdfBinário do PDF, direto na resposta.
pngimage/pngBinário do PNG, direto na resposta.
bothapplication/json{ pdf_base64, png_base64 }

Aviso de simulação

Este projeto existe para simular, em ambiente de teste, o comprovante de um banco — nunca para produzir um documento que possa passar por um comprovante real. Por isso, de propósito:

  • O nome do banco é sempre fictício ("ColmeIA Bank"), fixo no código.Não é configurável por request — evita qualquer confusão com uma instituição real.
  • Toda página traz uma marca d'água "SIMULAÇÃO" e o selo "DOCUMENTO SIMULADO — SEM VALOR FISCAL OU BANCÁRIO".Visível em qualquer PDF ou PNG gerado, sem exceção.
  • O rodapé identifica que o arquivo foi gerado por um simulador, com data e hora.
⬡

Remover esses avisos para produzir um comprovante que pareça autêntico pode configurar fraude. Este projeto é só para testes internos e demonstrações.
